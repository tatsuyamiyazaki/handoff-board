# 人間ボードは created_by で作成者本人のタスクに絞る

## Status

accepted

## 決定

人間（カンバンWeb UI）が読むボードは、**そのユーザーが作成したタスクのみ**を表示する。

- `Task` に `created_by: string | null` を追加。作成時に作成主体（人間=サインインメール、機械系=トークン種別）を記録する（`buildTask` が `actor` を格納）。
- `GET /api/board` は認証種別で挙動を変える:
  - **人間**（Firebase Bearer）→ `findAll({ createdBy: <当人メール> })` で自分の作成分のみ。
  - **機械系**（X-Board-Token：ディスパッチャー/AI）→ `findAll()` でボード全体（絞り込まない）。
- Web は人間ログイン専用とし、未ログイン時は機械系トークンへフォールバックせず、ボードを取得しない（サインイン促しのみ表示）。

## 文脈とトレードオフ

従来、未ログインのブラウザが開発用 `X-Board-Token` にフォールバックしていたため、サインインしなくても全タスクが見えていた。要件は「未ログインでは見せない」「ログインユーザーに紐づくタスクのみ」。

「紐づく」の定義として検討:

1. **owner（human/ai-batch/...）で絞る** — 却下。owner は"役割"であって個人ではない。ユーザー個別の絞り込みにならない。
2. **assignee を新設して担当者で絞る** — 見送り（将来拡張）。アサインUIと運用が必要で、初手としては重い。
3. **採用案: created_by（作成者）で絞る** — 「自分が始点のタスク（AIに渡した needs-ai を含む）」が自然に自分のボードに乗る。handoff の「人間が起票しAIへ渡す」流れに合致。スキーマ追加1フィールドで完結。

機械系を絞らないのは、ディスパッチャー/AI は board 全体から次の作業を拾う必要があるため（人間ごとの区切りは機械系には無意味）。絞り込みは人間パス限定とする。

## 帰結

- `TaskRepository.findAll(filter?: { createdBy })` に絞り込みを追加。Firestore 実装は `where('created_by','==',email)` でクエリ段階フィルタ。
- `created_by` 追加前に作成された既存タスク（フィールド無し / 機械系トークン作成分）は、人間がサインインしても**当人の created_by と一致しないため表示されない**。移行が必要なら別途バックフィルする。
- Web は Firebase サインイン必須になった。ローカルでも Firebase 設定（VITE_FIREBASE_*）が無いと人間ボードは見られない（機械系は API 直叩き/ディスパッチャーで従来どおり）。
